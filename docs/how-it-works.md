# How it works

## The pieces

| Piece | Where | What it is |
|---|---|---|
| Launcher patch | `tcl-tv-kit/launcher-local-changes.patch` | Changes to the Clean Your TV launcher (package `com.gathin.tvhome`) plus the new files, against upstream commit `b06ab21105c49900cb1ed76b24414dba1e21d0db`. Applied by `bootstrap.sh` |
| Weather feed | `tcl-tv-kit/weather-feed/` | A headless app, package `local.tvweather`, about 11 KB. The only part with internet access |
| Debloat lists | `tcl-tv-kit/debloat/` | Seven batches for `pm disable-user`, plus `KEPT.txt` |
| Theme | `tcl-tv-kit/theme/` | Wallpapers and `config.json`, pushed with the upstream `tools/theme.sh` |
| Icons | `tcl-tv-kit/icons/` | SVG sources and `build_icons.py`, which turns them into Android vector drawables |
| Scripts | `tcl-tv-kit/*.sh` | Thin wrappers around the upstream tools that set the options this TV needs |

Everything about how the launcher looks and behaves is set in one file, `launcher/app/src/main/res/values/config.xml`. The new behaviour is behind switches there
(`square_tiles`, `weather_provider`, `back_starts_screensaver`, `glass_style` = `lift`), each described in the file. **But not everything is behind a switch:** a few shared styles and drawables
are changed outright (the top buttons' size and glass, the popup glass, the clock and date sizes and the header layout in `activity_main.xml`). Turning the switches off therefore gives the
stock *tiles* in a changed header, not the untouched upstream look, and that combination was not tested.

## What the patch changes

### Square glass cards (`AppAdapter`, `MainActivity`)

`square_tiles`, `square_tile_dp` (the card edge, 86 dp) and `square_tile_aspect` (height as a percentage of width, 90) turn the 16:9 tiles into rounded squares (corner radius 22% of the
width). The row is centred by giving the grid equal side padding. The app name is drawn inside the card, just under the logo. Each card's artwork is a layered drawable generated by
`icons/build_icons.py` (see below).

### Frosted glass (`GlassBackdrop`)

Android 11 has no live backdrop blur, and blurring the whole screen every frame is too heavy for a TV like this. So:

1. When the wallpaper is decoded (`WallpaperPlayer`), it is also drawn into a **192 x 108** bitmap, blurred with two box-blur passes (about a 20 px blur at 1080p), and pushed
   through a small saturation boost (1.35) because glass looks richer than what is behind it.
2. Each glass surface (card, weather pill, top-bar button, library panel) gets a `BackdropDrawable` as the bottom layer of its background. It paints the **slice of that blurred bitmap that
   lies behind the view**, using the view's on-screen position (not its window position, which matters for popups), and repaints when the view moves or the wallpaper changes.
3. The surface's own glass goes on top: a smoky veil, a faint diagonal light, a flat whisper of the app's colour, and a hairline edge.

Cost: a few milliseconds per wallpaper change and an 80 KB bitmap. With no wallpaper there is no blurred copy and the surfaces keep plain glass. This deliberately breaks upstream's "no blur"
rule; it is the main reason this is a patch and not a pull request.

### Focus without an overlay (`LiftSheen`, `AppAdapter`)

Upstream moves one floating highlight between tiles with a spring. Here the highlight is switched off while `square_tiles` is on, and the **card itself** reacts: it scales to 1.12,
rises 7 dp, and fades in a foreground drawable (`LiftSheen`) with a slightly brighter surface, a diagonal sheen from the top-left and an edge lit from above. Nothing slides between cards.
(`GlassView` also has a `lift` style, selected with `glass_style`, for the case where the overlay is used.)

### Weather pill (`WeatherLine`)

With `weather_provider` set (here `local.tvweather`), Home reads one row from `content://local.tvweather/now` while it is on screen, and shows the temperature, a drawn weather symbol, and an
air-quality dot and index. Nothing runs while Home is paused. The launcher's manifest has no `INTERNET` permission and still does not: it only reads another app's content provider.
The symbols and the dot are drawables, not font glyphs, so the line centres exactly.

### App library (`AppLibraryDialog`)

With `square_tiles` on, the library becomes a frosted panel with compact cards (about 104 x 112 dp), the app's own icon, a 12 sp name, a small check on apps that are on Home, and the same
rise-by-itself focus. The sliding highlight is not created. The shared `glass_panel.xml` (Inputs dropdown, options menus) is now translucent smoky glass too.

### Back on Home (`MainActivity`)

With `back_starts_screensaver`, Back on the plain Home screen starts the TV's screensaver through the system's "start now" shortcut (`com.android.systemui/.Somnambulator`), or the launcher's
clock where the firmware has none. Back is ignored for 0.7 s after Home appears, so leaving an app with a double press does not start it. Popups, the library and reorder mode take Back first.

### Also configured here

`dock_apps`, `hidden_apps`, `app_banners`, `app_keys` (one TCL remote's coloured buttons), `settings_key_keycodes`, `consume_volume_keys` (with the key helper bound, this TV's volume keys step twice per press
unless the helper consumes them), `date_below_clock`, `library_button`, `icon_only_buttons`.

## The icon pipeline

`icons/build_icons.py` reads SVGs (`dl/` from Simple Icons, CC0; `custom/` drawn by hand) and writes `glyph_<name>.xml` (the logo as a vector drawable) and `banner_<name>.xml` (the glass layers
around it). The SVGs are treated as untrusted: only `d`, `fill` and `stroke` of `<path>` elements are read, each checked against a whitelist before it goes into XML. The generated
drawables are already in the patch; you only run the script to add or change a logo.

## The weather feed (`local.tvweather`)

A content provider with one URI, `content://local.tvweather/now`, read-only, returning one row:

`temp`, `feels`, `high`, `low`, `condition`, `symbol`, `aqi`, `aqi_label`, `place`, `updated`, `aqi_source`

- A query that finds the data older than 25 minutes starts one background fetch (at most one per 2 minutes) and returns the cached row meanwhile. There is no service, no alarm and no boot receiver:
  the app only runs while the launcher asks.
- Weather and the air-quality index come from Open-Meteo for the coordinates in `strings.xml`.
- **Optional IQAir key.** `content call --uri content://local.tvweather --method set_key --arg <key>` stores a key; with one, the index comes from IQAir's nearest-city reading and
  `aqi_source` says `iqair`. The call is accepted only from the ADB shell (uid 2000) or root, checks the key's shape (36 hex digits and dashes), and the key is stored in the app's private storage and
  is never returned by `query`. `./set-aqi-key.sh` wraps it and reads the key from your keyboard with no echo.
- **Why the index can differ from another app:** the model value is a 24-hour average of a satellite-assisted model on a coarse grid. On the author's TV it read 128 while a station-based app read about 87.

## TCL's rule for apps that start in the background

TCL's firmware (`TclAppBoot`) refuses to start an app's provider or accessibility service while the app has not been launched, unless the app holds the `APP_AUTO_START` app-op. The install scripts
grant it (`appops set <pkg> APP_AUTO_START allow`, then `appops write-settings` so a reboot does not drop it). Without it the weather pill simply stays hidden.

## Security model

- The launcher has no `INTERNET` permission. Only the feed app does, and it exposes no write path except the shell-only key setter.
- Debloat is `pm disable-user`, recorded and reversible. The scripts refuse any list that disables Android's core packages.
- ADB is plaintext on port 5555. It is only on while you work; the guide ends with turning it off and checking the port.
- No credentials, Wi-Fi names, addresses or device identifiers are in this repository, and the scripts never write your API key to a file or show it on screen. (It does pass through the command line of `tv.py` on your computer and of `content` on the TV for a moment, so don't run it on a shared machine.)

## Where it differs from upstream, honestly

- The blur (above).
- `square_tiles` and the lift focus are local switches in code that upstream does not have. The upstream tile code paths are kept when they are off, but see the note at the top: it was only tested with them on.
- Upstream asks contributors not to change defaults for every TV; these changes are meant to be applied as a patch for one TV, not merged.
